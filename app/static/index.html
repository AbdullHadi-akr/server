Lokale Modelle in VS Code

Auf … laufen die Modelle qwen3:30b-a3b und qwen3-coder:30b unter Ollama. Diese Seite zeigt, wie du sie in den VS-Code-Chat einbindest, und prüft auf Knopfdruck, ob der Server sauber antwortet.

Einrichtung in VS Code

  1. Zugangsschlüssel holen

    Am Portal anmelden, die Seite Konto öffnen und dort Neuen Schlüssel erzeugen drücken. Der Schlüssel (mp_…) erscheint nur dieses eine Mal im Klartext, also gleich kopieren.

    Noch kein Konto? Ein Administrator legt es an und nennt dabei Benutzername und erstes Passwort.

  2. Modellverwaltung öffnen

    Strg+Shift+P drücken und Chat: Manage Language Models auswählen.

  3. Endpunkt anlegen und Schlüssel eintragen

    Add Models → Custom Endpoint. VS Code fragt nacheinander nach der Adresse und nach einem API-Key:

    URL
    … (ohne /v1, das hängt VS Code selbst an)
    API-Key
    der eigene Zugangsschlüssel aus Schritt 1

    Danach Enter drücken, bis sich die Datei chatLanguageModels.json öffnet.

  4. Vorlage ersetzen

    Das automatisch erzeugte Template komplett löschen und stattdessen den folgenden Inhalt einfügen, dann speichern (Strg+S):

    ⚠️
    Die Adresse hat sich geändert
    wird geladen …

    Beide Modelle stehen in einem gemeinsamen Anbieter-Eintrag, du musst die Prozedur also nur einmal durchlaufen. Der Schlüssel steht bewusst nicht in dieser Datei: VS Code verwahrt ihn getrennt und schickt ihn als Authorization-Kopfzeile mit.

  5. Modell im Chat wählen

    Im Chat-Fenster oben rechts die Modellauswahl öffnen und … auswählen.

    Die erste Antwort kann verzögert kommen, weil Ollama das Modell erst in den Speicher lädt. Alle weiteren Antworten kommen dann zügig.

Funktionsprüfung

Prüft, ob Ollama erreichbar ist, ob beide Modelle installiert sind und ob der OpenAI-kompatible Endpunkt (/v1/chat/completions), den VS Code anspricht, korrekt antwortet.

Wenn etwas nicht klappt

„No response“ oder Timeout beim ersten Prompt
Normal beim Kaltstart: Das 30B-Modell wird geladen. Einmal abwarten und die Anfrage wiederholen.
VS Code meldet, der Endpunkt sei nicht erreichbar
Die url in der Konfiguration muss vom Arbeitsplatz aus erreichbar sein, ohne /v1 am Ende. Das hängt VS Code selbst an. Test im Terminal: curl …/api/version
401 oder „kein gültiger Zugangsschlüssel“
Der eingetragene API-Key fehlt, ist veraltet oder gehört zu einem gesperrten Konto. Unter Konto einen neuen Schlüssel erzeugen und ihn in VS Code hinterlegen: Strg+Shift+P → Chat: Manage Language Models, dort den Anbieter-Eintrag erneut öffnen. Ein neuer Schlüssel macht den alten sofort ungültig.
Anfragen werden mit Hinweis auf eine Reservierung abgewiesen
Jemand hat für dieses Zeitfenster Slots reserviert. Die Meldung nennt wer und bis wann. Später erneut versuchen oder unter Reservierungen selbst eines eintragen.
Modell taucht in der Auswahl nicht auf
JSON-Syntax prüfen (jede Zeile außer der letzten im Objekt braucht ein Komma) und VS Code neu laden: Strg+Shift+P → Developer: Reload Window.
Ollama antwortet nur auf dem Server selbst
Ollama mit OLLAMA_HOST=0.0.0.0:5020 starten, sonst lauscht der Dienst nur auf 127.0.0.1.
Modell fehlt auf dem Server
ollama pull qwen3:30b-a3b bzw. ollama pull qwen3-coder:30b
